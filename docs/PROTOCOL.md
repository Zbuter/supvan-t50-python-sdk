 SUPVAN T50 协议说明

本 SDK 同时支持目标 `supvan-cups` 所使用的原生 USB 协议和 T0 BLE 协议。两者共享打印数据的 4096 字节帧和 LZMA-Alone 压缩格式，但外层传输不能混用。

## 原生 USB 流程

USB 使用厂商控制请求和 64 字节 HID 报告。典型打印流程为：

1. 按需使用 `0x30` 读取耗材盒数据；缺少介质宽度、高度或间隙时由 SDK 自动读取。
2. `0x5D` 写入 80 字节介质配置。
3. `0x12` 检查设备，随后用 `0x11` 等待设备空闲。
4. `0x13` 开始打印。
5. 对压缩数据重复执行 `0x5C` 传输、HID 写入和 `0x10` 缓冲确认。
6. 用 `0x11` 轮询打印页数和打印状态；超时或异常发送 `0x14`。

图像帧为 4096 字节，前 14 字节是帧头，位图按行、低位在前打包；USB 路径在送入帧编码前执行水平镜像。HID 输出按 64 字节分片，并保留整除 64 时追加的零尾报告，这是 Windows 厂商驱动的兼容行为。

## BLE 差异

BLE 使用 `0x7E 0x5A` 外层帧、16 位小端校验和及 GATT 分片。BLE 图像按列打包，每列固定 48 字节并按 `y % 8` 使用低位优先，画布在发送前旋转 90 度；USB 则按行打包，按 `x % 8` 使用低位优先，并在发送前水平镜像。两者不能共用位图方向处理。

BLE 大块打印数据使用 `0xAA 0xBB` 内层分包和 512 字节外层封装，每个内层包最多携带 500 字节；USB 使用压缩块直接传输，不包含 BLE 的 `AA BB`、包序号和 500 字节分包层。BLE 默认每批最多 4 个逻辑帧，USB 默认每批最多 8 个逻辑帧，且 USB 将打印速度通过 `0x10` 的第二个参数下发。

## 实现约束

- `PrintSettings` 的介质宽度、高度和间隙可以从 `0x30` 响应补齐，显式值优先。
- `direction`、`dpi` 和 `max_dot_value` 在生成 USB 帧前校验，避免产生设备无法处理的图像尺寸。
- 状态响应保留原始 8 字节标志，并在 USB、BLE 两条路径映射为同一 `PrinterStatus` 模型。
- 协议构帧函数拒绝超出线缆字段宽度的命令、参数和分包编号。
